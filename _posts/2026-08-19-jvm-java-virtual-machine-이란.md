## JVM이 정확히 무엇인가? 그리고 어떤 역할을 하는가?

* 자바 바이트코드(.class 파일)를 실행하기 위한 가상화된 계산 환경이자 실행 엔진입니다. OS와 자바 애플리케이션 사이에서 동작하며, "Write Once, Run Anywhere(한 번 작성하면 어디서든 실행된다)"라는 자바의 핵심 철학을 실현하는 중심축 역할을 합니다.

![](/assets/img/posts/diagram-1-jvm-architecture.png)

#### **플랫폼 추상화 계층**

* JAVA는 OS 위에 JVM이라는 추상화 계층을 두어서 OS나 CPU가 달라져도 코드를 다시 컴파일하거나 재작성할 필요가 없습니다

#### 바이트코드 실행기

* JVM의 역할은 자바 컴파일러가 생성한 바이트코드를 읽어 실제 CPU가 이해할 수 있는 기계어로 해석하고 실행하는 것입니다. 이를 위해 다음과 같은 내부 컴포넌트들이 협업합니다.
* **Class Loader(클래스 로더)**
  컴파일된 `.class` 바이트코드 파일들을 동적으로 읽어들여 JVM의 메모리 영역에 로드, 링크, 초기화합니다.
* **Execution Engine (실행 엔진)**
  메모리에 로드된 바이트코드를 명령어 단위로 가져와 실행합니다. 실행 방식은 두 가지가 혼용됩니다.
      - **인터프리터(Interpreter)**
      바이트코드 명령어를 한 줄씩 읽어서 기계어로 해석하고 실행합니다. 초기 실행 속도는 빠르지만, 반복되는 코드도 매번 해석하므로 전체 실행 속도가 느릴 수 있습니다.
      - **JIT 컴파일러(Just-In-Time Compiler)**
      자주 실행되는 코드 영역(Hot Spot)을 감지하여, 해당 바이트코드 전체를 미리 기계어로 변환(컴파일)하고 캐싱해 둡니다. 이후 해당 영역은 해석 과정 없이 직접 기계어로 실행되어 Performance를 향상시킵니다.
* **Garbage Collector**
  Heap 메모리 영역을 지속적으로 모니터링하며, 더 이상 참조되지 않는 객체들을 자동으로 탐지하고 메모리에서 해제합니다. 개발자가 직접 메모리를 할당/해제할 필요 없도록 자동 관리합니다.
* 이 주제에 대해서는 추후 자세히 다루도록 하겠습니다

#### Runtime Data Area(메모리 관리 구조)

![](/assets/img/posts/jvm_runtime_data_area_memory.svg)

JVM이 OS로부터 할당받아 애플리케이션을 실행하는 동안 사용하는 메모리 영역입니다.

| **영역**                      | **설명**                                       | **공유 여부**  |
| --------------------------- | -------------------------------------------- | ---------- |
| **Method Area (Metaspace)** | 클래스 구조, 메타데이터, 메서드 코드, static 변수 등이 저장       | 모든 스레드 공유  |
| **Heap**                    | `new` 연산자로 생성된 모든 객체와 인스턴스 변수가 저장 (GC의 주 대상) | 모든 스레드 공유  |
| **JVM Stack**               | 메서드 호출 시마다 생성되는 스택 프레임. 지역 변수, 매개변수, 리턴값 저장  | 스레드별 독립 생성 |
| **PC Register**             | 현재 스레드가 실행 중인 JVM 명령어의 주소를 기록                | 스레드별 독립 생성 |
| **Native Method Stack**     | Java가 아닌 C/C++ 등 타 언어로 작성된 네이티브 코드를 실행할 때 사용 | 스레드별 독립 생성 |

JVM은 **자바 바이트코드를 기계어로 변환하여 실행하는 실행기**이자, **하부 OS 및 하드웨어 스펙을 추상화하여 동일한 실행 환경과 자동 메모리 관리(GC)를 제공하는 핵심 런타임 엔진**입니다.

## 자바가 아닌 다른 언어도 JVM 위에서 동작 가능한가?

JVM은 이름에 'Java'가 들어있지만, 실제로는 특정 언어가 아니라 **'자바 바이트코드(.class 파일 규격)'를 실행하도록 설계된 가상 머신**입니다. 따라서 어떤 프로그래밍 언어든 컴파일 결과물로 JVM 바이트코드 표준 사양을 만족하는 `.class` 파일을 만들어낼 수만 있다면 JVM 위에서 구동됩니다.

* 주요 JVM 언어 목록 - Kotlin, Scala, Groovy 등

## VM 사용의 장점과 단점

#### VM 사용의 장점

* **플랫폼 독립성과 이식성**
* **자동 메모리 관리 및 안정성** - 가비지 컬렉터(GC)가 사용되지 않는 메모리 자동 수거하므로, 메모리 누수나 잘못된 메모리 참조로 인한 시스템 붕괴 위험이 줄어든다
* **런타임 동작 최적화(JIT)** - 프로그램 실행되는 동안 실제 호출 빈도와 실행 패턴 분석해 자주 쓰이는 코드를 실시간으로 최적화된 기계어로 변환

#### VM 사용의 단점

* **초기 실행 속도 및 웜업(Warm-up) 시간**
* **높은 메모리 점유율**
* **가비지 컬렉션(GC)으로 인한 일시 정지**

## JVM과 내부에서 실행되고 있는 프로그램은 부모 프로세스 - 자식 프로세스 관계를 갖고 있다고 봐도 무방한가요?

JVM과 그 내부에서 실행되는 자바 프로그램은 완전히 별개의 프로세스로 분리된 것이 아니라, **하나의 프로세스 내부에서 함께 동작**합니다.

동일한 OS 프로세스 공간을 사용하고 JVM 프로세스 내부의 메인 스레드 위에서 실행되므로, 부모-자식 스레드가 아닙니다

#### JVM은 자바 프로그램이 실행되는 환경(Process Context) 그 자체입니다
